## Codebase Patterns
- Validators are kept in `convex/validators.ts` and imported into schema
- Use `v.optional()` for nullable fields in Convex schema
- Compound indexes follow pattern `by_field1_field2`
- Timestamps use `v.number()` storing `Date.now()` values
- Organization membership roles: owner, admin, member
- Utility functions go in `convex/lib/` directory
- Use `as const` for readonly arrays to enable type inference
- Import QueryCtx/MutationCtx from "../_generated/server" for typing
- Use Doc<"tableName"> from "../_generated/dataModel" for document types
- Discriminated unions with `type` field for multi-variant patterns
- Permission helpers in `convex/lib/permissions.ts` - use {allowed, reason} for error messages
- Better Auth setup: convex.config.ts (defineApp + app.use), auth.config.ts (AuthConfig with providers)
- Better Auth server: auth.ts exports authComponent (createClient), createAuth function, getCurrentUser query

- HTTP router in convex/http.ts - use httpRouter() and export default http
- authComponent.registerRoutes(http, createAuth, { cors: true }) for Better Auth route registration
- Auth client: lib/auth-client.ts with createAuthClient from better-auth/react + convexClient plugin
- Auth server: lib/auth-server.ts with convexBetterAuthNextJs from @convex-dev/better-auth/nextjs
- Auth API route: app/api/auth/[...all]/route.ts exports GET, POST from handler
- ConvexClientProvider: components/providers/convex-client-provider.tsx with ConvexBetterAuthProvider + QueryClientProvider
- TanStack Query setup: ConvexQueryClient connects to QueryClient via queryKeyHashFn and queryFn
- Better Auth to app user linking: authComponent.getAuthUser(ctx)._id → users.externalId
- Use safeGetAuthUser for nullable auth checks, getAuthUser when auth is required (throws)
- Auth pages: app/(auth)/ route group, use authClient.signIn.social for OAuth buttons
- Use @tabler/icons-react for icons (IconBrandGithub, IconBrandGoogle, etc.)
- TanStack Query patterns: useQuery(convexQuery(api.x.y, {})), useMutation with useConvexMutation(api.x.y)
- Client-side validation mirrors server validation for UX (validate before submit)
- Use internalQuery/internalMutation for functions only callable by HTTP actions (not exposed to client)
- HTTP actions: use httpAction from "_generated/server", ctx.runQuery/runMutation for internal calls
- HTTP route params: {param} syntax but parse manually from request.url (not auto-injected)
